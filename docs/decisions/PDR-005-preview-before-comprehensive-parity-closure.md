# PDR-005 — Deliver an installable preview before comprehensive parity closure

## Decision

Prioritize the distribution plan's package, first-battle documentation, and preview installation evidence before the next broad parity batch. The fidelity goal remains in force. A preview may carry clearly diagnosed limitations and open compatibility cases; it must state what users can install and run without representing battle completion as full Classic parity.

Startup failures, crashes, hangs, broken team operation, and basic behavior regressions receive priority within compatibility work. Diagnose subject, opponent-pool, harness, and engine failures separately. A difficult case retains its evidence and a useful next experiment or a stated information boundary; difficulty alone does not establish robot fault. Repair retests stay focused on the named cause and relevant regressions. Repeating a known score gap requires a hypothesis or a concrete delivery question.

Preview readiness requires a reproducible package, a documented compatible Java and Tank Royale runtime route, a disposable-environment first-run check, and a maintainer or user walkthrough. It must not rely silently on the maintainer's local caches or development builds. No outside volunteer is required. Publication, tags, and release timing require separate maintainer authorization.

## Rationale

People need a usable way to run their existing robots to benefit from fidelity repairs and report actionable failures. Comprehensive parity is a continuing quality objective whose statistical investigations should not indefinitely postpone installation and documentation. The distribution plan defines the concrete readiness work; the versioned registry continues to preserve every observed difference.
